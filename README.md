# NGU Save Tracker

An unofficial web tool for [NGU Idle](https://store.steampowered.com/app/1147690/NGU_IDLE/) players. Import your save
files to chart your progress, try gear swaps, and work out what to spend on next. Not affiliated with the game's
developers.

## Features

- **Progress:** charts and a day-by-day table across all your saves, with run and challenge bands.
- **Rates and targets:** gains per day, time for each NGU to reach a target level, and a milestone timeline.
- **Gear what-if:** swap items and see the effect on your stats, or find the best gear for a goal.
- **Calculators:** EXP spending and energy/magic balance, best augment pair, and fruit timing.
- **Compare saves:** every field that changed between two saves, with item names.

## Privacy

Saves are parsed and stored only in your browser (IndexedDB), and nothing is uploaded. The production build's
Content-Security-Policy blocks all network requests. Saves contain your player name, which the app doesn't display, so
treat a downloaded backup like a save file.

## Accuracy

Formulas are written for game build 1260 and may be off on other builds. Results haven't all been compared with the
game's own screens. Known limits are stated next to each tool.

## Development

    npm install
    npm run dev      # local development
    npm test
    npm run build    # static site in dist/, deployable to any static host

- `src/save/`: NRBF parser, save decoding, metrics, run grouping, save diff
- `src/stats/`: stat formulas, gear what-if, and EXP, augment and fruit calculators
- `src/store/`: IndexedDB storage, import, backup
- `src/charts/`, `src/views/`: UI
- `src/data/itemNames.ts`: item names, generated by `tools/gen_item_names.py`

Metrics are re-derived from stored originals when `METRICS_VERSION` in `src/save/metrics.ts` is bumped.

The tests use a synthetic save fixture. Further suites compare results with real saves and values from a private
reference model, and they skip themselves when that data isn't present, as in a fresh clone or CI. To run the real-save
suite against your own saves, point `NGU_SAVES_DIR` at your save folder. No game files, saves or description text are
in this repo.

## Deploying

`npm run build` writes a static site to `dist/`. Asset paths are relative and navigation uses the URL hash, so it works
from any path (for example `/tools/ngu-save-tracker/`) without server rewrites. The Content-Security-Policy is a `<meta>`
tag in the built page; a host that can set headers should also send `frame-ancestors 'none'` (or
`X-Frame-Options: DENY`) and `X-Content-Type-Options: nosniff`, which a `<meta>` tag can't set.
